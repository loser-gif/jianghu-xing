# 江湖行

支持桌面与手机的文字武侠 RPG。当前杭州篇包含探索、人物关系、武学修为、自动战斗、问心试炼塔、生活百业、年龄寿元与捕快身份，逐步扩展为沙盒武侠。

[在线试玩](https://loser-gif.github.io/jianghu-xing/) · [源码仓库](https://github.com/loser-gif/jianghu-xing)

## 本地运行

需要 Node.js 22.12 或更新版本。

```powershell
cd D:\JHX\jianghu
npm ci
npm run dev
```

打开终端显示的地址，默认 http://127.0.0.1:5173/ 。开发服务器只监听本机。

```powershell
npm test
npm run build
npm run preview
```

生产文件在 `dist/`。采用 Vite 相对资源路径与页面状态导航，部署在仓库子路径下时无须改写前端路由，刷新回到主菜单后可继续存档。

- 新增「百业生活」：药师采药炼药、铁匠采矿锻造、渔者垂钓烹饪。各职业独立从初学成长至学徒、熟手、名匠，可以兼修；采集 → 制作 → 每日订单 → 获得银两与熟练度形成闭环。客栈可出售材料和成品，药品和鱼汤可在行囊使用。
- 新增「岁序寿元」：一年十二月、每月三十日，一日六时段，每段两时辰。行动才推进时间，离线或停留页面不会消耗寿命；移动、生产和一般修习耗一时段，查看、换装、交易不耗时。
- 角色17岁入江湖，基础寿元80岁；随境界提高上限，宗师150、大宗师200、陆地神仙300、天人500、太朴1000岁。旧存档从本次迁移时开始计龄，不追扣历史年龄。
- 可安排1日、7日、30日或一年闭关，先预览再确认；获得修为但不自动突破，计时案件期间不可闭关。寿尽进入人生结算，停止推进并保留人物、行囊和手记，允许导出纪念存档、返回主菜单重开。
- 本轮106项测试与生产构建通过，真实浏览器验证生产交单、自动战斗暂停/倍速/刷新恢复、闭关增龄及寿尽结算；详见 `docs/LIVING_CALENDAR_QA.md`。

## 试炼与江湖路引（2026-10-08）

- 首页按状态推荐下一步；「玩法指引」常驻顶部。路引包含初行五步、六条玩法路线、资源含义、时间与存档规则、不可操作的常见原因。
- 初行顺序：检查行装 → 修习武学 → 试炼塔第一层 → 强化装备 → 首次破境。已完成自动勾选，随时可自由行动；已有存档无需重开。
- 西湖问心试炼30层，每5层守关。敌方意图提示守势、重击与破绽，成功防御重击后反击伤害 +50%；兵器与出战武学适配时试炼招式伤害 +20%。内功提高调息回气，轻功可闪避。
- 首通获修为、银两、精铁与试炼印；首通守关另获感悟与4点潜能。试炼印兑换补给、装备、轻功；潜能在人物页分配，不可撤回。
- 每层每游戏日最多一次奖励，首通奖励不重复；次日复战仅四分之一修为与银两。进入消耗两时辰，失败保留通关进度和物品，气血剩1。计时案件期间暂不开放入塔。
- 武器、衣甲、鞋履均可在铁匠铺强化至+5；每级武器外功+3、防具防御+2和气血上限+5。提高上限不自动回血。
- 修为中后段的案件/委托条件可用试炼塔15层/25层替代，玩家可以选择不走捕快路线。
- 当前仍只开放杭州。加入或自创宗门、更多朝廷官阶尚未实现，不将其列为可玩内容。

## 第一桩案子的走法

1. 创建角色，打开地图前往官府。
2. 拜见陆捕头，进入身份司簿，入职捕快。
3. 打开缉捕令，接取《烟雨楼盗案》。购买两条绳索、一条布条并完成准备。
4. 前往烟雨楼调查，再到后巷辨认线索。去东侧水路可抵旧码头；西巷是假线索，会损失时间和气血。
5. 前往旧码头拦下顾红绫。自动交锋可调整策略和速度；均衡策略会应对重击，稳守更注重调息，用药需勾选自动用药且占一回合。
6. 完全击败后可先救治、取证，再完成手部、腿部、示警三个控制状态。
7. 安全押送归案，领取 300 两、25 捕快声望、40 官府贡献；在官府申请晋升。

这只是最短路线。先帮助苏婉娘、认识白芷或向剑客学艺，会在任务中留下不同的记录。

## 存档

进度仅存放在浏览器 `localStorage`，键名前缀为 `jianghu.v1.`。自动存档键为 `auto`，手动槽为 `1`、`2`、`3`，新建角色及导入前的备份为 `previous`。不同域名、浏览器或设备的进度相互独立。

首次打开不会自动进入游戏；选择“继续游历”恢复自动存档。战斗回合、敌方气血、任务阶段、道具、关系记忆均保存。清理站点数据会移除存档，迁移设备前请导出 JSON。尚未接入云同步。

## 图片准备与动态主菜单

正式版使用 13 张经过 WebP 编码的画卷，合计由 14,380,418 字节降到 3,387,966 字节（减少约 76%），源画保留。动态菜单新增底图和人物图层合计 561,380 字节。`scripts/optimize_art.py`（Pillow）可重新编码并生成带内容哈希的图片和 `src/data/art-manifest.json`；日常构建直接使用已提交的结果。

进入主菜单前先准备并解码游戏插画，显示真实完成进度。图片保存在本站专用 Cache Storage 中，后续打开优先复用；文件内容变更时使用新文件名，清理仅限本游戏的过期画卷，不触及存档。缓存不可用时仍可请求网络，失败可重试或先进入。此功能是图片缓存，不是整站离线 PWA。

主菜单以 WebGL 分层绘制披风、下摆和发梢起伏、山谷流雾及树冠摆动。构图、建筑、人物脚底和持剑手保持稳定，文字和按钮独立渲染。右上角可暂停并记住选择；切到后台、打开主菜单弹窗时暂停，遵循系统减少动态效果设置。最多 30 帧/秒、约 125 万渲染像素，不额外下载视频；GPU 不可用时退回原静态画卷，游戏仍可操作。

隔离站点设置 HTTP `no-store` 后，首次请求 11 张插画，再次打开与进入人物页的新增插画请求为 0。另验证图片失败及恢复重试、动效暂停持久化与弹窗暂停。

动态分层升级验证：43 项测试、生产构建通过；390×844、320×700 和 1440×1080 浏览器检查通过。新增两张素材首访请求，再次刷新新增插画请求为 0。约 9 秒真实截图序列验证衣摆、发梢、枝叶和云层变化，以及固定脚底；另检查暂停、刷新后保留暂停选择和存档弹窗暂停。真实手机 GPU、系统减少动态效果及 WebGL 上下文丢失未进行实体设备实测。
